# 広告・お布施(応援)配置メモ

> おうちのおつかいアプリ向けの収益化・応援機能の配置案。実装前の検討メモ。

## 前提
- 家族向けのおつかいPWA(4タブ: お買い物 / ミッション / ストック / 設定)。
- **子どもも使う**(ミッション機能)ため、広告はファミリー向け/非パーソナライズが必須(COPPA等のポリシー注意)。
- 静的PWA + ログイン構成。AdSenseは独自ドメイン+審査が必要なため、まずは審査不要の**お布施リンク**から始め、広告は後追いが安全。
- クリーンな実用UIが強みなので、広告は最小限(リスト末尾1枠 + 完了時リワード程度)に絞るのを推奨。

## 広告(さりげなく、操作の邪魔をしない場所)

| 候補 | 場所 | 評価 |
|------|------|------|
| リスト末尾インフィード | お買い物タブ `#list-done` の後 / ストックタブ `#stock-ok-section` の後 | ◎ コンテンツの邪魔をせず自然。最下部で誤タップも少ない |
| 完了時リワード広告 | おつかい完了 / ミッション達成のモーダル | ○ 区切りが自然。「動画を見てごほうび+」など報酬型と相性良い |
| 設定タブ末尾 | ログアウトカードの下 | ○ 低頻度だが無難 |
| (避ける) | bottom-nav 周辺・FAB付近・各シート内の操作領域 | ✗ 誤タップ/操作妨害でUX悪化 |

## i-mobile 実装メモ

### 配置済みスポット
mid は媒体（PC=593256 / SP=593257）単位で共通、asid が配置ごとに個別。

| 配置 | スポット名 | PID | SP (mid/asid) | PC (mid/asid) |
|------|-----------|-----|---------------|---------------|
| ログイン画面 (`#ad-slot-auth`) | ログイン画面 バナー | 84969 | 593257 / 1932940 | 593256 / 1932939 |
| お買い物タブ末尾 (`#ad-slot-requests`) | アプリ内画面 | 84969 | 593257 / 1943162 | 593256 / 1943160 |
| 紹介ページ 最後のCTAとフッターの間 (`index.html` の `#ad-slot-lp`) | トップ画面 | 84969 | 593257 / 1943161 | 593256 / 1943159 |

`index.html` は `app.html` の JS を読み込まない独立した静的ページのため、
`injectImobileBanner()` は使えず、同等の注入処理を `index.html` 内に複製している。

### 仕組み
- `#list-done` の再描画で消えないよう `#tab-requests` 直下の兄弟要素として配置。
- `injectImobileBanner(slotId, config)` が `navigator.userAgent` と `matchMedia("(max-width: 767px)")` で端末判定し、**SP/PC のどちらか片方のタグだけを差し込む**(規約: SP/PC タグの混在禁止)。
- `spot.js` ローダーは `data-imobile-loader` 属性で重複読み込みを防止。複数スロット追加時もローダーは 1 回のみ。
- 「広告」ラベルを `--muted` カラーで明示(`.ad-label`)。
- 広告SDKが実際に中身を描画したときだけ（`MutationObserver` で検知）`.ad-slot` に `has-ad` クラスが付き表示される。タグを差し込んだだけの空枠では出さない（広告ブロッカー・在庫切れ等で中身が入らないとき、「広告」ラベルだけの空枠が出ていた不具合の修正）。

### 残タスク / 追加候補
- ✅ i-mobile 管理画面のアダルトフィルタは「強+」設定済み（子ども利用前提のため必須）。
- 効果を見て、② ストックタブ末尾 / ③ 設定タブ末尾 / ④ 完了履歴シート末尾 に追加検討。追加時は新スポット作成 → `initAdSlots()` に `injectImobileBanner(...)` 呼び出しを追加するだけ。

### 媒体審査NGの経緯（2026年8月時点）

i-mobileへの媒体掲載申請が「弊社規定によりNG」（詳細理由の開示なし）で却下された。
アダルトフィルタは既に「強+」で設定済みのため、これが原因ではなさそう。
最有力の疑いは**独自ドメインでないこと**（現状は`b-w-hiroki.github.io/otsukai/`という
共有プラットフォームのサブパス）。`release-plan.md`にある独自ドメイン取得を先に検討する。

### 続報（2026年9月）: 独自ドメインでも NG → 紹介ページを用意

独自ドメイン `otsukai.birdman-studio.com` に移行後も PC / SP とも「弊社規定によりNG」。
同じアカウントの別サイト（おさんぽビンゴバトル）は承認されているため、ドメイン種別ではなく
**審査担当者がトップURLを開いてもログイン画面しか見えず、内容を確認できない**ことが原因と判断。

対策として、ルートの `index.html` をログイン不要の**紹介ページ**（機能・画面・使い方・運営者情報・
規約/ポリシー/問い合わせへのリンク）にし、アプリ本体を `app.html` に移した。
再申請は `https://otsukai.birdman-studio.com/`（紹介ページ）の URL で行う。
あわせて i-mobile パートナーサポートに NG 理由の問い合わせも送る（返答があればここに追記）。
