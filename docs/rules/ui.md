# UI ガイドライン — おうちのおつかい

画面ごとに見た目や操作がバラつかないよう、**ボタンの配置と種類のルール**を決めておく。
新しい画面や機能を足すときは、まずここを見て既存のクラスを使う。

---

## 1. ボタン配置の規則

| 場面 | 置き場所 | 理由 |
|---|---|---|
| **画面・シートの主操作**（追加する / 閉じる / 終了する） | **下部・全幅** | 片手で親指が届く。指の移動距離が最小 |
| **行ごとの操作**（買うよ / 買ったよ / コメント） | 行の**右端**、右寄せ | 視線が品名 → 状態 → 操作の順に流れる |
| **破壊的操作**（削除・統計リセット・アカウント削除） | **トグルの内側**に隠す＋必ず `confirm` | 誤タップの防止。日常操作の隣に置かない |
| **補助操作**（編集・⭐・金額） | 行タップで開く**詳細エリア**の中 | 常時表示すると品名を圧迫する |
| **フローティング**（よく買うもの / ＋追加 / 店内。お買い物ページのみ） | フッター上部・**横1列** | 片手で届く位置に集約。右下に別の＋を浮かせると重なって見えるため、この列に含める |

### 具体例
- 履歴シート・店内モード → 閉じる/終了は**下部全幅**（位置差8px以内で揃える）
- 買い物リストの行 → ◯（左）＋ 品名（中央）＋ 操作（右端）
- 設定タブの管理系 → 「🔧 管理メニューを開く」トグルの内側

## 2. ボタンの種類

`styles.css` の共通クラスを使う。**インラインスタイルで新しい見た目を作らない**。

| クラス | 用途 | 見た目 |
|---|---|---|
| （素の `button`） | 主操作 | 紫グラデ＋白文字 |
| `.ghost` | 副操作 | 枠線のみ |
| `.danger` | 破壊的操作 | 赤 |
| `.success` | 完了・肯定 | 緑 |
| `.btn-neutral` | 設定・メンテナンス系 | グレー地＋枠線 |
| `.btn-block` | 全幅にする（併用） | — |
| `.btn-stack` | 縦並びの間隔（親に付ける） | — |
| `.section-toggle-btn` | 折りたたみの見出しボタン | 枠線＋シェブロン ▾/▴ |
| `.store-mode-close-btn` | シート/全画面の下部・閉じる | 全幅・グレー |
| `.sheet-footer` | シート下部の固定領域（親） | 上境界線つき |
| `.seg-control` / `.seg-btn` | **タブ内をさらに切り替える**（例: ミッションタブの ⚡/🎁/🎯） | 角丸ピル・選択中は白背景+紫文字。`.seg-btn` は最小高さ44px確保済み |
| `.settings-acc-hdr` | **カード自体を開閉する**（例: 設定タブの各カード） | 見出し全幅＋右端に回転シェブロン。`.settings-acc`（親カード）に `closed` を付け外しする。最小高さ44px確保済み |
| `.topbar-icon-btn` | **コア機能ではない副次的な導線**をトップバーに置く（例: 🏆ミッション） | 円形アイコンボタン（44×44px）。`.howto-btn`（？ボタン）と対の位置（名前と？の間）に置く想定 |

### 注意（実装時の落とし穴）
グローバルの `button` に紫グラデ＋白文字＋ホバーが当たっているため、
**独自スタイルのボタンは `background` / `color` / `:hover` を明示的に上書きする**こと。
これを忘れると「文字が白背景に白文字で消える」不具合になる（過去に発生）。

## 3. タップ領域

- 最小 **44×44px**（アイコンのみのボタンは 38px 角＋余白で実質44px以上）
- 破壊的ボタンは、頻繁に押すボタンから **8px 以上**離す

---

## 4. 色の使い分け

| 意味 | トークン |
|---|---|
| 主体・リンク | `--pri` / `--pri-dark` |
| 未受付 | `--c-open`（青） |
| 宣言済み・進行中 | `--c-claimed`（オレンジ） |
| 完了 | `--c-done`（緑） |
| 急ぎ・危険 | `--c-urgent`（赤） |

**ハードコードした色を書かない**。ダークモードは CSS 変数の差し替えで実現しているため、
生の `#hex` を書くとダークで破綻する。

---

## 5. シートの作り方

```html
<div id="xxx-sheet" class="sheet">
  <div class="sheet-handle"></div>
  <div class="sheet-content">          <!-- ここがスクロール領域 -->
    <div class="sheet-header">…</div>  <!-- sticky。タイトルのみ -->
    <div id="xxx-body">…</div>
  </div>
  <div class="sheet-footer">           <!-- 下部固定 -->
    <button class="store-mode-close-btn">✕ 閉じる</button>
  </div>
</div>
```

`.sheet` は `max-height: 88dvh` の flex 縦積み。**この構造から外れると、中身が長いときに
画面外へはみ出して閉じられなくなる**（過去に発生した不具合）。

## 7. PC幅（広い画面）での見え方

このアプリは元々スマホ専用に作っており、`.app` の中身は `max-width:680px` で
中央寄せされる。**固定配置の要素（トップバー・下部ナビ）もこの680pxに揃える**こと。
揃えないと、広い画面でコンテンツ列だけ中央に浮き、バーだけ画面端まで伸びて
不格好になる（実際に発生した不具合）。

- トップバーは `.topbar-inner`（中身側）に `max-width:680px; margin:0 auto;` を常時指定
  （680px未満では無効になるだけなので、モバイル用に別途分岐しなくてよい）
- 下部ナビは `@media (min-width:720px)` で `left:50%; transform:translateX(-50%); width:680px;`
  に切り替える（`left/right` 指定のままだと `max-width` と competing してセンタリングできないため）
- 下部ナビは今 `1fr` 均等割り5列で、中央（3列目）に**お買い物タブ**を丸く浮かせて置いている
  （＋ボタンは画面右下に独立して浮かせてあり、下部ナビの列には含まれない）。
  中央のボタンとその背面のクレードル（`.bottom-nav::before`）は
  **同じグリッド列に explicit に置く**こと。片方だけ更新して列がズレると、
  auto配置される他のタブがその列を避けて詰まり、ナビが2段に折り返す
  （実際に2回踏んだ不具合。＋がここにあった頃と、お買い物に差し替えたときの両方）。
  （以前は `::before` を `.fab::before` にしていたが、負のz-indexが
  同じ要素の背景より前面に出てボタン自体が真っ白に潰れるので避けている）
